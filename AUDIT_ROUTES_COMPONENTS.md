## Scope, method, and interpretation

- Inspected `AGENTS.md`, `tsconfig.json`, and the installed Next 16.4.3 page, route-handler, and route-group guides. Route groups are removed from URLs; `[param]` denotes a dynamic URL segment. `/` is the home page. Every row is a **framework entry**: Next discovers it without an inbound source import. Framework discovery does not establish that a user has navigated to it.
- Enumerated every `src/app/**/page.tsx` and `src/app/**/route.ts` directly from the filesystem, without a truncated glob listing. Each appears exactly once below. URL columns describe framework paths, without query strings, auth availability, redirects, or deployment rewrites.
- Parsed 616 repository TS/TSX/JS/JSX/MTS/MJS/CTS/CJS modules with TypeScript 5.9.3. Resolved imports using the actual TypeScript compiler options (bundler resolution and `@/*` → `src/*`). Counted import declarations (including type-only), export/re-export barrels, import-equals, literal `import()`, and literal `require()`. Barrel edges are counted at each module, not mistaken for absent direct imports. Existing CSS imports were resolved by exact file fallback. No nonliteral dynamic import/require was found; no local import remained unresolved. The parser never executes imported application modules.
- Scanned current source, repository scripts/tests, and root configuration modules; excluded dependencies, `.git`, generated `.next`, `.claude` worktrees, public assets, SQL migrations, and scratch `tmp`. Runtime caller evidence below comes from `src`, not assertions or source-text reads in tests. Module inbound results include all scanned modules.
- Caller evidence records representative file:line references for links, navigation data, fetches, URL builders, shared helper arguments, endpoint props, and literal route imports. Template interpolation is represented symbolically; query builders and concatenation are considered. Static routes take precedence over a dynamic sibling. **URL reference; caller not proven** identifies weaker evidence. A constant or allowlist is not promoted to an actual invocation. Shared fetch helper/endpoint prop evidence was source-checked for the cited helpers.
- Tables provide up to four representative caller/reference sites per entry, prioritizing explicit calls/navigation. They are exhaustive in entry rows, not every reference occurrence. Server domain imports are separately shown (up to three per entry) to document direct server wiring; importing a domain function does **not** prove an HTTP request to that API. A missing HTTP caller may coexist with a page importing the same domain module directly.
- **No explicit caller found** means this static pass did not establish one; it never means dead, safe to delete, inaccessible, or unused in production. External integrations, stored CMS URLs, user bookmarks, cron/provider configuration, computed strings, server actions, and references outside scan scope remain limits. This is an inbound-module audit, not export-level tree shaking or reachability from application roots: an imported module can still be in a disconnected subgraph, and a type-only edge is still an inbound edge.
